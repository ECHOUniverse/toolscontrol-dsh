# Desktop 真机手动验收清单（未自动验收）

本清单验收基线为 Desktop 0.2.2-rc.1。自动化覆盖包括：单元/行为测试（vitest）、产物契约测试、离线 envelope smoke（`pnpm smoke`）；当前 `pnpm verify` 的 14 个测试文件、264 个用例已通过。**GUI 行为与真实 Desktop 集成未做自动化验收**；以下清单按真机证据逐项勾选，未实际执行的项不得勾选。

## 前置条件

- [x] Desktop `0.2.2-rc.1`（`dsh` 引擎窗口 `>=0.2.1-rc.1 <0.3.0-0` 内）
- [x] 已构建产物：`pnpm verify` 全绿；或直接使用 `pnpm pack` 产出的 tarball
- [ ] 安装方式二选一（`<profile>` 填自己的 profile 名；**不能填 `desktop`**——该 profile 由 Desktop（Electron）应用独占，通用 `dsh` CLI 会直接拒绝，rc.5 上实测的报错原文：`error: profile "desktop" is managed exclusively by the Electron application`）：
  - 通用 CLI：`dsh plugin --profile <profile> add link:/absolute/path/to/toolscontrol-dsh`（或 npm 包名 `@hanxu131/toolscontrol-dsh`）
  - Desktop 插件页 **添加插件 / 安装第三方插件** 对话框：填本地目录绝对路径或压缩包路径（Desktop 自带官方文档说明接受包名、Git 地址、压缩包或本地绝对路径，且仅接受声明 bundle patch 的包；该说明在 rc.5 时确认，本插件的 `cordis.patch.yml` 满足）——**此 GUI 安装流程对本插件未真机验收，本次验收即为首次验证**
- [ ] 打开插件页（侧栏 Plugins）

- [ ] 默认只显示 `enabled=true` 的条目；切换“已禁用 / 全部”筛选行为正确
- [ ] 名称搜索不区分大小写，与状态筛选可组合
- [x] 每行状态徽标显示“未知”（rc.1 无连接状态观测）；不以 fiberPhase、工具是否存在、插件加载状态或探测结果替代；**探测成功后状态仍为“未知”**
- [x] 行内不显示实时工具数量；工具数量只出现在手动探测结果中（见第 4 节）
- [ ] 页面说明区分“连接状态”与“连接探测”，不声称当前版本具备连接状态观测
- [ ] **preset-only MCP 不丢失**：仅配置在 agent preset 组合内的 MCP server（profile 根级没有对应行）出现在列表中，并标注“Preset：<名称>”；profile 根级条目标注“DSH profile 根级”
- [ ] **同名跨作用域分别展示**：同一名称同时存在于 profile 根级与 preset 时是两行，行为/详情各自独立，不合并、不冒充全局项
- [ ] **条件启用**：preset 行的 `disabled` 为表达式时显示“条件启用”，不显示为普通“已启用”
- [ ] **诚实空态**：profile 根级与全部 presets 都被完整读取且无 MCP 时显示“当前 DSH profile / presets 未配置 MCP server（…未读取外部 CLI 配置）”，不是泛泛的“当前范围内没有条目”；`pluginInventory` 不可用或读取不完整（组装面/条目无法解析）时显示通用空态 + warning，不断言“未配置”
- [ ] **enabled 不可默认启用**：MCP 行 `enabled` 缺失或非 boolean/`'conditional'` 时该行被跳过、warnings 说明原因，不显示为已启用
- [ ] 存在重复条目或畸形清单（preset 缺 id / rows 非数组）时页面 warnings 给出说明，快照不整体失败
- [ ] 手动刷新后“上次刷新”时间更新；断开 Host 后刷新失败时保留旧数据并出现过期提示
- [ ] 行内展开：连接状态“未知”、作用域、来源、已配置四项；仅已启用且可探测条目出现“探测”入口；键盘 Tab 可达、Enter 展开、`aria-expanded` 正确

## 4. 连接探测（手动）

准备：至少一个已启用的 `streamable-http` 条目、一个已启用的 `stdio` 条目、一个无 Tools 能力或 0 工具的条目、一个已禁用条目，以及一个 `disabled` 为表达式、静态无法求值的 preset 条目。

2026-11-11 真机证据：用户截图确认 `include:mcp-anysearch`（streamable-http）手动探测成功，返回 5 个工具，展示观测时间、耗时与工具名，且连接状态保持“未知”。stdio、Preset、失败、取消与清理路径仍须分别实测。

- [ ] **不自动探测**：打开页面、手动刷新、切换筛选 / 工作区 / 会话后，均无“探测中”状态、无探测请求、无 stdio 子进程；任何位置都不出现自动探测
- [ ] **入口范围**：仅已启用且可探测条目出现“探测”入口；已禁用条目、不可探测条目没有可用入口
- [x] **单条探测成功路径**：点击“探测”后显示“探测中…”；成功显示探测时间、工具数量与可展开的工具名
- [ ] **单条探测失败路径**：失败显示脱敏原因
- [ ] **成功判定**：无 Tools 能力或工具数为 0 时仍显示探测成功（例如“未返回任何工具”但成功），不误报为失败
- [ ] **全部探测**：只对当前筛选结果中的已启用且可探测条目逐个探测；改变筛选后再次“全部探测”，范围随筛选变化，不包含已禁用或不可探测条目
- [ ] **超时**：对无响应的条目，单次探测约 10 秒后结束并显示失败；不阻塞其他条目或整页
- [ ] **并发上限 2**：Host 实际执行的探测连接最多两个，其余请求排队等待；同一条目在探测进行中重复点击不产生第二个底层连接
- [x] **成功结果独立于连接状态**：探测成功后连接状态徽标仍为“未知”，不显示为“已连接”
- [ ] **失败结果独立于连接状态**：探测失败后连接状态徽标仍为“未知”，不显示为运行时“失败”
- [ ] **结果生命周期**：探测结果只保留在当前页面会话（非 DSH 会话）；刷新页面后结果清空，离开页面 / 卸载插件后不保留
- [ ] **stdio 清理**：stdio 探测结束后短期子进程退出；取消探测、离开页面、卸载插件时进行中的子进程被终止，系统进程列表无残留
- [ ] **传输与协商**：`streamable-http` 与 `stdio` 均可探测；版本协商（`versionNegotiation`）为 `auto`，无需用户手动选择协议版本
- [ ] **错误脱敏**：页面、网络响应、控制台 / 日志、错误详情中不出现 env / headers / token / command / URL；仅显示脱敏后的原因
- [ ] **凭据边界**：凭据只在 Host 内存使用，不进入 Client DTO、日志、持久化或错误详情；探测请求只含稳定条目探测键，不含配置
- [ ] **不可探测**：已禁用、所需内部接口缺失、传输或配置不受支持、Preset 动态配置无法可靠求值时，条目标“不可探测”并说明原因；MCP 配置总览、筛选与其他条目不受影响
- [ ] **内部接口缺失降级**：在缺少 loader / agentPresets 内部面的环境中，探测降级但配置总览仍可读取；不得据接口存在推断连接状态
